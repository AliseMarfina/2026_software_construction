# Контракты API

Формат для каждого эндпоинта: метод, путь, авторизация, тело запроса/параметров, тело ответа, коды ошибок. Нефункциональные требования (latency) даны отдельным пунктом на каждый эндпоинт и сводной таблицей в конце — выводятся из профиля нагрузки, рассчитанного в Capacity Planning (пиковая нагрузка ≈ 54 оп/сек), и учитывают, что часть операций зависит от внешнего API (Open Food Facts), а часть — чисто внутренние.

**Общие соглашения:**
- Формат: JSON, `Content-Type: application/json`
- Авторизация: `Authorization: Bearer {accessToken}` для всех эндпоинтов, кроме регистрации/логина
- Коды ошибок: 400 (невалидные данные), 401 (не авторизован), 403 (нет прав на ресурс), 404 (не найдено), 409 (конфликт), 503 (недоступен внешний API)
- Latency измеряется на стороне сервера (без учёта клиентского RTT), в процентилях p95/p99 под пиковой нагрузкой ≈ 54 оп/сек

## Auth

### `POST /api/auth/register`
Регистрация пользователя.

Запрос:
```json
{ "username": "string", "email": "string", "password": "string" }
```
Ответ `201 Created`:
```json
{ "id": 123, "username": "string", "email": "string" }
```
Ошибки: `409` — email/username уже занят, `400` — не прошла валидация (короткий пароль, некорректный email).

**NFR:** p95 < 300 мс, p99 < 600 мс/

### `POST /api/auth/login`
Аутентификация.

Запрос:
```json
{ "email": "string", "password": "string" }
```
Ответ `200 OK`:
```json
{ "accessToken": "string", "expiresIn": 3600 }
```
Ошибки: `401` — неверные email/пароль.

**NFR:** p95 < 300 мс, p99 < 600 мс.

## Products

### `GET /api/products/search?q={query}`
Поиск продукта: сначала по `product_cache` и `user_custom_foods`, при отсутствии совпадений — запрос к Open Food Facts с последующим кэшированием результата.

Параметры: `q` (строка, минимум 2 символа)

Ответ `200 OK`:
```json
[
  {
    "source": "cache",
    "barcode": "4607034910073",
    "name": "Куриная грудка филе",
    "kcalPer100g": 113,
    "proteinPer100g": 23.6,
    "fatPer100g": 1.9,
    "carbsPer100g": 0.4
  },
  {
    "source": "custom",
    "id": 45,
    "name": "Мамина запеканка",
    "kcalPer100g": 180,
    "proteinPer100g": 9.5,
    "fatPer100g": 8.0,
    "carbsPer100g": 18.0
  }
]
```
Ошибки: `400` — `q` короче 2 символов, `503` — внешний API недоступен и по запросу нет закэшированных совпадений.

**NFR:**
- **Cache hit** (~90% запросов, только чтение из PostgreSQL): p95 < 150 мс, p99 < 300 мс
- **Cache miss** (round-trip до Open Food Facts + запись в кэш): p95 < 1200 мс, p99 < 2500 мс — зависит от латентности и rate limit внешнего провайдера, не полностью контролируется бэкендом

### `POST /api/products/custom`
Добавление собственного продукта пользователем (когда не нашёлся в поиске).

Запрос:
```json
{ "name": "string", "kcalPer100g": 0, "proteinPer100g": 0, "fatPer100g": 0, "carbsPer100g": 0 }
```
Ответ `201 Created`: тот же объект с `id`.

**NFR:** p95 < 200 мс.

## Diary

### `POST /api/diary`
Добавить запись в дневник. Ровно одно из полей `productBarcode`/`customFoodId` должно быть заполнено.

Запрос:
```json
{ "productBarcode": "4607034910073", "customFoodId": null, "grams": 150 }
```
Ответ `201 Created`:
```json
{
  "id": 5821,
  "productName": "Куриная грудка филе",
  "grams": 150,
  "kcal": 169.5,
  "protein": 35.4,
  "fat": 2.85,
  "carbs": 0.6,
  "loggedAt": "2026-09-29T13:05:00Z"
}
```
Ошибки: `400` — заполнены оба поля или ни одного, `404` — указанный продукт/кастомная еда не существует.

**NFR:** p95 < 200 мс, p99 < 400 мс.

### `PATCH /api/diary/{id}`
Изменить граммовку существующей записи. Требуется владение записью (запись принадлежит текущему пользователю).

Запрос:
```json
{ "grams": 200 }
```
Ответ `200 OK`: обновлённый объект записи (формат как у `POST`).

Ошибки: `403` — запись принадлежит другому пользователю, `404` — не найдена.

**NFR:** p95 < 200 мс.

### `DELETE /api/diary/{id}`
Удалить запись. Владение проверяется так же, как в `PATCH`.

Ответ: `204 No Content`.

Ошибки: `403`, `404`.

**NFR:** p95 < 150 мс.

### `GET /api/diary/day?date=YYYY-MM-DD`
Сводка за конкретный день.

Ответ `200 OK`:
```json
{
  "date": "2026-09-29",
  "totalKcal": 1850,
  "totalProtein": 120.4,
  "totalFat": 65.2,
  "totalCarbs": 180.0,
  "entries": [
    { "id": 5821, "productName": "Куриная грудка филе", "grams": 150, "kcal": 169.5 }
  ]
}
```

**NFR:** p95 < 200 мс, p99 < 400 мс (один индексированный запрос по `(user_id, logged_at)` + агрегация в БД).

### `GET /api/diary/stats?from=YYYY-MM-DD&to=YYYY-MM-DD`
Статистика КБЖУ по дням за период. Максимальный диапазон ограничен одним годом.

Ответ `200 OK`:
```json
{
  "days": [
    { "date": "2026-09-23", "kcal": 1820, "protein": 115, "fat": 60, "carbs": 175 },
    { "date": "2026-09-24", "noData": true }
  ],
  "average": { "kcal": 1795, "protein": 118, "fat": 62, "carbs": 172 }
}
```
Ошибки: `400` — диапазон превышает допустимый лимит или `from > to`.

**NFR:** p95 < 400 мс, p99 < 800 мс (более тяжёлый запрос: группировка по датам на большем количестве строк, чем у `day`).
