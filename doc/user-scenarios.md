# Пользовательские сценарии: трекер калорий

## Сценарий 1: Добавление приёма пищи

**Актор:** пользователь
**Цель:** записать, что он съел

**Предусловия:** пользователь авторизован, находится на главном экране

**Основной поток:**
1. Пользователь нажимает "Добавить запись".
2. Вводит название продукта в поле поиска (например, "куриная грудка").
3. Видит список подходящих продуктов с указанием калорийности на 100 г.
4. Выбирает нужный продукт из списка.
5. Указывает граммовку (например, 150 г).
6. Подтверждает добавление.
7. Видит обновлённую сводку калорий за день с учётом новой записи.

**Альтернативный поток:** нужный продукт не нашёлся в результатах поиска → пользователь выбирает "Добавить свой продукт", вводит название и КБЖУ на 100 г вручную, дальше продолжает с шага 5.

**Результат:** запись о приёме пищи добавлена в дневник.

## Сценарий 2: Просмотр сводки за день

**Актор:** пользователь
**Цель:** узнать, сколько съедено сегодня

**Предусловия:** пользователь авторизован

**Основной поток:**
1. Пользователь открывает главный экран (раздел "Сегодня").
2. Видит суммарные калории и БЖУ за день.
3. Видит список всех добавленных за день записей (продукт + граммовка).
4. При необходимости нажимает на конкретную запись, чтобы отредактировать граммовку или удалить её.

**Альтернативный поток:** за сегодня ещё ничего не добавлено → пользователь видит пустую сводку (0 ккал) и предложение добавить первую запись.

**Результат:** пользователь понимает текущий дневной баланс и может скорректировать записи.

## Сценарий 3: Просмотр статистики за период

**Актор:** пользователь
**Цель:** оценить, укладывается ли он в целевые показатели за последнее время

**Предусловия:** пользователь авторизован, есть хотя бы одна запись в дневнике

**Основной поток:**
1. Пользователь открывает раздел "Статистика".
2. Указывает начальную и конечную дату периода, за который хочет посмотреть статистику.
3. Подтверждает выбор.
4. Видит график КБЖУ по дням за указанный период, где для дней без записей отображается "нет данных" (а не ноль).
5. Видит средние значения по калориям и БЖУ, рассчитанные только по дням, за которые есть данные.

**Альтернативный поток:** у пользователя нет данных за часть или весь выбранный период (например, он не вёл дневник в эти дни, либо указал даты раньше момента регистрации) → все дни без записей в этом промежутке одинаково отображаются как "нет данных", без ошибок и специальных сообщений; расчёт средних значений при этом опирается только на те дни, где данные фактически есть.

**Результат:** пользователь видит тренд КБЖУ за выбранный им самим период и может сравнить его с целью.
